# Локальный запуск MAI Food

Эта инструкция описывает изолированную демонстрацию из репозитория. Выполняйте команды в корне рабочей копии, содержащей `infra/local-demo.py`.

## Что нужно

- Запущенный Docker Desktop с Docker Compose v2.
- Python 3 для управляющего скрипта и OpenSSL для первоначального создания ключей.
- Интернет при первой сборке контейнеров. Node.js и Python-зависимости сервисов на компьютере
  не нужны: приложения собираются и работают внутри Docker.

## Запуск

В терминале:

```sh
python3 infra/local-demo.py up --open
```

Скрипт собирает приложения, запускает отдельный проект `mai-food-demo`, применяет миграции,
создаёт локальную тему Kafka, запускает приём событий и Outbox, добавляет демонстрационные
данные и открывает Mini App с локальной тестовой личностью. На первой сборке нужно подождать
несколько минут. Повторный запуск сохраняет данные; повторно меню и исходные заказы не создаются.
Если будущие слоты закончились, команда `seed` добавляет новые. При балансе ниже 1000 ₽ эта
команда пополняет демонстрационный кошелёк на 2000 ₽; не запускайте её во время проверки
недостаточного баланса. Обычная команда `up` тоже вызывает `seed`.

Адреса:

| Что открыть | Адрес |
| --- | --- |
| Меню, корзина, профиль, собственные заказы | http://localhost:8180 |
| Кухня, касса, администрирование | http://localhost:8181 |
| Swagger User Service | http://localhost:8180/api/v1/users/docs |
| Swagger Menu Service | http://localhost:8180/api/v1/menu/docs |
| Swagger Order Service, включая демооплату | http://localhost:8180/api/v1/orders/docs |

Используйте именно `localhost`, поскольку вход проверяет разрешённый адрес страницы.
PostgreSQL и Kafka демонстрации занимают порты 5544 и 9192.
Порты сервисов опубликованы только на этом компьютере.

## Вход и просмотр результата

Mini App открывается как **Анна Демонстрационная**. Это синтетическая личность для отдельного
локального сервера; реальный Telegram или токен BotFather не нужны. Приложение проходит обычную
серверную проверку подписанных данных и получает обычную сессию. Если вход не восстановился или ссылка устарела, создайте новую:

```sh
python3 infra/local-demo.py login --open
```

Ссылка действует пять минут. Она также сохраняется в `.private/local-demo/client-url.txt` внутри
демонстрационного каталога. Не переносите тестовый токен, ключи или `.env` в публичное окружение.
Сохранение сессии использует Secure HttpOnly cookie; при ограничениях браузера для HTTP localhost
повторите вход командой выше. Полная проверка реального Telegram и HTTPS остаётся отдельной задачей.

Для страницы сотрудников доступны логины:

| Логин | Возможности |
| --- | --- |
| `demo-admin` | Все заказы, меню, категории, блюда, слоты |
| `demo-cook` | Очередь приготовления, начало готовки, отметка готовности |
| `demo-cashier` | Готовые заказы и выдача |

Общий случайно созданный пароль находится в поле `password` файла
`.private/local-demo/access.json` **внутри демонстрационного каталога**. Файл локальный, не хранится
в Git. Откройте его в локальном редакторе.
Если сессия сотрудника истекла, войдите снова.

В базе подготовлены шесть блюд с фотографиями, четыре будущих слота и три заказа: ожидающий, готовящийся и
готовый. Время слотов демонстрационное,
отображается по Москве с отметкой МСК; это не расписание
реальной столовой.

Проверьте сценарий:

1. Откройте Mini App, добавьте блюда в корзину и выберите будущий слот.
2. Оформите заказ, откройте билет и историю. Перезагрузка страницы сохраняет корзину и сессию;
   незавершённая отправка восстанавливается с исходным ключом в той же вкладке.
3. Войдите на 8181 как повар: переведите заказ в приготовление, затем в готовность.
4. Обновите собственный билет Mini App: статус изменится. Очередь кухни также опрашивает сервер.
5. Войдите как кассир и выдайте готовый заказ. Для проверки отмены создайте отдельный заказ и
   отмените его до начала слота, пока он ещё ожидает приготовления.
6. Войдите как администратор и проверьте изменение меню и управление слотами. Валидация формы
   слотов использует настройки интерфейса; это не утверждённый производственный календарь.

## Демонстрационный баланс и Swagger

В сборке включена серверная демооплата: создаётся синтетический баланс, создание заказа
списывает деньги, допустимая отмена возвращает их один раз. Реальных списаний нет.
Mini App показывает баланс и состояние оплаты. Для ручного начисления используйте Swagger.

1. В Swagger User выполните `POST /auth/staff` с логином `demo-admin` и локальным паролем.
2. Скопируйте `access_token` ответа в `Authorize` Swagger Order (HTTP Bearer).
3. Для `POST /wallet/credits` укажите новый UUID в заголовке `Idempotency-Key` и тело:

```json
{
  "user_id": "UUID клиента из client_id в локальном access.json",
  "amount": 100000
}
```

Это 1000 ₽: API принимает целые копейки. Строку-пример `user_id` замените реальным UUID.
Повтор того же ключа и тела не начисляет деньги повторно. `GET /wallet` показывает баланс
авторизованного пользователя; с ADMIN-токеном это кошелёк администратора, а не клиента.
Клиент получает свой токен при `POST /auth/telegram`; для обычного сценария достаточно уже
открытой Mini App и подготовленного баланса.

## Состояние, журналы и остановка

Все команды ниже выполняются из демонстрационного каталога:

```sh
python3 infra/local-demo.py status
python3 infra/local-demo.py down
```

`down` останавливает только `mai-food-demo`, сохраняет базы и Kafka и не трогает старый стенд.
Чтобы запустить снова, выполните `up --open`.

Для просмотра журналов конкретного сервиса:

```sh
docker compose -p mai-food-demo -f docker-compose.yml -f compose.local-demo.yml logs --tail 100 order-service
docker compose -p mai-food-demo -f docker-compose.yml -f compose.local-demo.yml logs --tail 100 notification-inbox outbox-worker
```

После отказа worker может остановиться намеренно. Сначала изучите журналы и восстановите
зависимость, затем повторите запуск. При расхождении сохранённых позиций Kafka восстановление
требует отдельной проверки: не удаляйте данные и не сбрасывайте позиции наугад.

## Что включено и что ещё впереди

Демо включает меню с шестью фотографиями, корзину, сессию Mini App, заказы со слотами по Москве,
демонстрационный баланс и рабочее место сотрудников. Outbox публикует события демонстрационной
базы, Notification сохраняет их. Очередь кухни обновляется опросом API.

Для реального Telegram и Cloudflare Pages используйте отдельную
[инструкцию Cloudflare Tunnel](docs/deployment/cloudflare-tunnel.md).
Она использует настоящий токен бота, поэтому синтетическая ссылка запуска работает только
в локальной конфигурации.

## Перенос на другой компьютер

Склонируйте репозиторий в отдельный каталог. Запустите `python3 infra/local-demo.py up --open`
из рабочей копии, содержащей скрипт. При первом запуске он создаёт собственный `.env`, ключи
и пароль. На Windows/Linux без `--open` используйте свежую ссылку
из `.private/local-demo/client-url.txt`.

Если Docker не отвечает — запустите Docker Desktop. Если заняты 8180/8181/5544/9192, сначала
освободите их или согласованно измените порты, адреса в скрипте и allowlist в Compose override.
Не используйте `down --volumes` для устранения проблем: это удаляет локальные данные.
